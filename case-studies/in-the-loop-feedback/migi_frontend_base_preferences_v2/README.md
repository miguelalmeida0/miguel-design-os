# Migi Frontend Base Preferences

This folder is a **master frontend/UX preference base** for future projects.

It is **not** a design system for one app. It must not force future projects to reuse any specific content, color palette, layout, app concept, or copy from previous projects.

Use this folder to understand Migi’s taste, UX standards, and recurring frontend expectations before starting implementation.

## How agents should use this

1. Read `docs/internal/automation/AGENTS.md` first.
2. Read `01_project_intake.md` before making design decisions.
3. Use `02_design_preferences.md` and `03_interaction_grammar.md` to guide UX/UI choices.
4. Use `04_anti_patterns.md` to avoid repeated failures.
5. Use `05_component_standards.md` for reusable frontend patterns.
6. Use `06_review_checklist.md` before reporting completion.

## Critical clarification

Migi does **not** want all projects to share the same colors, content, layout, or brand world.

Future projects must have their own visual identity. This folder captures broad preferences such as clarity, polish, hierarchy, responsiveness, premium interaction quality, and anti-slop standards.
