# Ghostwritter Style Report

## Product Personality

Ghostwritter is theatrical but controlled. It feels like a rewrite studio, not a generic AI text box. The page has a strong concept, a real visual character, and a tactile control system, but it avoids random decoration and keeps the core flow obvious.

## Visual System

- Canvas: deep near-black
- Typography: serif-led editorial headline with sans/mono support
- Accent: voice-specific colors that change selected states and CTAs
- Surfaces: translucent, dark, low-contrast cards with thin borders
- Artwork: responsive bitmap hero asset, integrated into the first viewport
- Motion: rewrite playback and small control transitions, with reduced-motion handling

## Hierarchy And Composition

The first screen has one literal offer: rewrite anything with a selected author. Below it, the page moves from choice to input to output:

1. Hero and primary action
2. Author/outcome controls
3. Mood dial
4. Composer and playback

Reusable principle: expressive apps still need a clean task spine. Drama works because the user can instantly see what to do.

## Interaction Grammar

- Author cards are buttons with clear selected vs unselected states
- Author/outcome mode toggle is a segmented control
- Mood is a slider with labels and visible progress
- Primary rewrite CTA is filled and voice-colored
- Quick starts are secondary chips
- Result tools are icon buttons and post-result actions
- How-it-works content lives in a drawer, not in the main flow

## Responsive Behavior

- Hero type clamps across viewports
- Artwork swaps between small, medium, and desktop assets
- Author grid collapses from four columns to two
- Studio composer/playback collapses to one column
- Overflow rules preserve one native document scroller

## Reusable Lessons

- Use a memorable first-viewport object when the product is experiential
- Scope visual systems under a root class to prevent bleed
- Make selectable cards visually unmistakable
- Make the AI process visible through state and playback, not through vague copy
- Prefer one strong control per concept: mode toggle, card grid, mood dial, composer

## Do Not Globalize

Do not copy the dark literary theme, author concept, or hero illustration into unrelated apps. The reusable lesson is concept-fit, strong first-screen promise, scoped tokens, and expressive controls with crisp state.
