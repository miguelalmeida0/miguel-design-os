# 00 — Global Frontend Principles

This is the broad master layer for all future apps.

It is not tied to any single previous project.

## Universal rules

- Every new project must get its own visual identity.
- Never force a universal color palette.
- Never copy old app content, labels, layouts, or product concepts.
- Extract principles, not app-specific features.
- Use semantic tokens instead of random one-off colors.
- Design direction must come from the project type, user, mood, and core action.
- Keep one clear primary purpose per screen.
- Make the main action obvious quickly.
- Make clickable and passive elements visually distinct.
- Use progressive disclosure instead of showing every option.
- Avoid container soup, chip soup, CTA soup, and fake dashboard energy.
- Prefer polished composition over stacked generic cards.
- Keep copy short, human, and contextual.
- Build responsive layouts that feel designed on desktop and mobile.
- Use modular Tailwind components.
- Avoid AI slop.

## Not universal

Do not force these on every project:

- light UI
- warm palette
- social tone
- playful copy
- card deck layouts
- friend/avatar concepts
- invite flows
- bottom nav
- mobile-first social structure

Use them only when the product actually needs them.
